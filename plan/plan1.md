### 第二部分：其余后端接口分析

#### 接口1：`GET /api/stats/dashboard`

**业务用途**：获取仪表盘页面展示的全局统计数据（如问答次数、检索耗时等）。

**请求方式**：GET

**核心入参**：无

**核心返回**：
- `qaCount: number`
- `todayQaCount: number`
- `avgRetrievalTimeMs: number`
- `retrievalTimeTrend: string`

**技术实现要点**：
- **Controller 层**：无需特殊参数校验，直接调用 Service。
- **Service 层**：
    1. 统计全局问答表/日志表中的总记录数。
    2. 统计今日（基于当前日期）的问答记录数。
    3. 计算所有问答记录（或近N条）的平均检索耗时。
    4. 计算今日与昨日的平均耗时差值，格式化为趋势字符串（如 "↓ 18%"）。
- **数据库操作**：查询问答记录表（如 `qa_records` 或 `chat_logs`），涉及 `COUNT` 和 `AVG` 聚合查询。
- **外部依赖**：无。
- **依赖关系**：
    - 不依赖其他接口先执行。
    - 需要在 Dashboard (SystemPage) 页面加载完成后立即调用。
- **预估复杂度**：低。均为简单的聚合 SQL 查询，业务逻辑不复杂。

---

#### 接口2：`GET /api/system/health/models`

**业务用途**：获取系统底层模型的健康状态，供仪表盘展示。

**请求方式**：GET

**核心入参**：无

**核心返回**：
- `embeddingModelLoaded: boolean`
- `llmBackendReachable: boolean`

**技术实现要点**：
- **Controller 层**：无需特殊参数校验，直接调用 Service。
- **Service 层**：
    1. 检查本地 ONNX 模型服务（或相关进程）是否已成功加载并就绪。
    2. 向配置的 LLM 后端（如 Gemini/DeepSeek API）发送一次极轻量的 Ping/探测请求。
    3. 捕获超时或异常，包装为布尔值返回。
- **数据库操作**：无。
- **外部依赖**：依赖本地 Embedding 进程及外部 LLM API 网络连通性。
- **依赖关系**：
    - 不依赖其他接口先执行。
    - 需要在 Dashboard (SystemPage) 页面加载完成后调用，建议开启短轮询（如 30s）。
- **预估复杂度**：中。需要妥善处理外部 API 的网络超时与异常捕获，避免接口长时间阻塞。
