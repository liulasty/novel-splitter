## pipeline

`pipeline` 模块是本系统业务流程的“总指挥”，其核心职责是通过管道模式（Pipeline Pattern）对复杂的小说处理任务进行优雅的编排与管理。由于小说的读取、拆分、校验与存储是一个多步骤且相互依赖的长耗时过程，该模块将整个处理流水线拆解为多个高内聚、低耦合的独立阶段（Stage）。其主要功能包括：定义标准的 `Stage` 接口契约，实现顺序执行的 `SequentialPipeline` 引擎，并统筹加载（Load）、拆分（Split）、验证（Validation）和保存（Save）等各个具体环节。在执行过程中，它能够安全地传递上下文状态，并在遇到异常时提供统一的错误处理与状态管理。在依赖关系上，该模块作为流程的枢纽，横向依赖于 `domain`（领域模型）、`splitter`（拆分逻辑）、`validation`（质量校验）和 `repository`（数据持久化）等多个业务模块。这种管道化的架构设计极大地增强了系统的可扩展性，使得未来新增处理环节（如自动打标签、敏感词过滤等）只需实现新的 Stage 接口并注册到管道中即可。

**典型使用场景与入口类说明：**
* 核心入口类为 `com.novel.splitter.pipeline.impl.SequentialPipeline`，它负责实例化并按顺序串联执行各个处理阶段。
* 在处理用户上传或下载的大规模小说文件时，应用层会直接调用 Pipeline 启动整个自动化拆分与入库流程。
* 开发者可以通过实现 `Stage` 接口来快速扩展新的数据处理环节，而无需修改现有的核心调度逻辑。
