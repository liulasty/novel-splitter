## repository

`repository` 模块在系统的领域驱动设计架构中扮演着数据持久化层的关键角色，其核心职责是负责所有核心领域实体的数据存取逻辑，并严格实现由领域层（`domain` 模块）定义的各种仓储（Repository）接口。当前阶段，该模块的主要功能集中在基于本地文件系统的数据持久化机制上。它能够将抽象的领域模型（如小说元数据、经过智能拆分后的场景片段等）安全、高效地转换为特定的存储格式（例如 JSON 文件）并落盘保存，同时支持从磁盘中反向加载这些数据结构。在依赖关系方面，该模块向上依赖于 `domain` 模块以获取标准的实体定义和仓储接口契约，向下则紧密依赖于 `infrastructure` 模块以利用其底层的文件 I/O 和序列化工具。这种设计确保了业务逻辑与具体存储技术的解耦，使得未来若需将存储介质从本地文件系统无缝迁移至关系型数据库或 NoSQL 数据库时，只需在本模块内新增实现类，而不会对核心业务流程造成任何冲击。

**典型使用场景与入口类说明：**
* 核心接口为 `NovelRepository` 和 `SceneRepository`，它们定义了数据存取的标准行为规范。
* 典型的具体实现类如 `LocalFileNovelRepository`，它是整个 Pipeline 处理流程中“保存阶段（Save Stage）”的核心驱动引擎。
* 在 RAG 检索或后续数据校验环节，其他模块会通过本模块提供的仓储接口，快速从本地存储中检索并加载所需的小说与场景数据。
