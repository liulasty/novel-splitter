## domain

`domain` 模块是本系统（基于领域驱动设计架构的智能化小说拆分与 RAG 系统）的核心基石，主要负责定义系统的核心业务模型和领域实体。为了确保业务逻辑的纯粹性与高可移植性，该模块在设计上被严格限制，不依赖于任何重量级的外部框架（如 Spring 框架）。其主要功能是全面封装小说处理过程中的关键业务概念，包括但不限于小说本体（Novel）、章节（Chapter）、场景（Scene）以及语义段（SemanticSegment）等核心领域实体。此外，它还详细定义了各种段落类型（如对话、叙述等）以及标准的回答模型，从而为后续的文本拆分、向量化存储和智能检索等复杂业务流程提供了统一且标准化的数据流转结构。在外部依赖方面，本模块保持了极高的独立性，仅引入了 `jackson-annotations` 以支持必要的 JSON 序列化与反序列化操作，以及 `lombok` 来有效简化实体类中样板代码的编写工作。这种轻量级的设计不仅降低了模块间的耦合度，还极大地提升了系统的可维护性和扩展性。

**典型使用场景与入口类说明：**
* `com.novel.splitter.domain.model.Novel` 与 `Scene` 是贯穿整个系统处理生命周期的核心流转对象，在加载、拆分、存储等环节被广泛传递。
* 作为架构的最底层，本项目中的其他所有业务模块（如 `splitter`、`pipeline`、`repository` 等）均需强制依赖此模块以获取统一的数据模型标准。
* 在与外部系统交互或进行持久化时，实体类上的 Jackson 注解确保了领域模型能够被准确、高效地转换为 JSON 格式。
