# 测试、可观测性与验收门禁

## 1. 背景与目标
手机端上线风险主要来自设备差异与弱网不稳定。该文档定义全链路测试策略、监控指标和发布门禁，确保可控上线。

## 2. 范围
### In Scope
- 功能测试、联调测试、弱网测试、兼容测试、回归测试。
- 移动端核心埋点与业务指标。
- 发布前验收门禁。

### Out Scope
- 非移动端功能的全量重测。
- 后端压测方案细节。

## 3. 测试分层
- **单元测试**：页面状态机、工具函数、错误映射。
- **集成测试**：页面 + hooks + API mock 的关键路径。
- **E2E 测试**：上传、轮询、问答、失败重试闭环。
- **专项测试**：弱网、前后台切换、低电量模式、机型兼容。

## 4. 核心用例池
- T-01：上传成功并进入处理队列。
- T-02：处理中前后台切换后状态恢复。
- T-03：任务失败后可一键重试并重新进入轮询。
- T-04：知识库删除操作成功并即时刷新。
- T-05：聊天切换小说版本后答案来源正确。

## 5. 可观测性指标
- 上传成功率
- 任务提交成功率
- 任务完成率
- 任务平均完成时长
- 问答成功率
- 页面崩溃率

## 6. 告警建议
- 上传成功率低于阈值触发告警。
- 任务失败率短时激增触发告警。
- API 错误率持续上升触发告警。

## 7. 验收门禁（Release Gate）
- P0/P1 缺陷必须清零。
- 主链路 E2E 用例通过率 100%。
- 兼容清单机型（Android/iOS 主流）全部通过。
- 弱网场景可恢复性通过。

## 8. 角色分工
- FE：修复前端功能与交互问题。
- BE：修复契约和状态可观测问题。
- QA：执行测试计划并出具验收报告。
- PM：签署业务验收与发布批准。

## 9. 任务拆解
- QA-TST-01：建立移动端测试用例库与执行节奏。
- FE-TST-01：补齐关键页面状态机测试。
- OPS-TST-01：接入上线指标监控与告警。

## 10. 风险与待确认
- 若缺少稳定测试环境，E2E 结果可能波动。
- 设备覆盖不足会导致上线后长尾兼容风险。
